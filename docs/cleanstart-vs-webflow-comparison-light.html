01 · Executive Summary

What changed, and why it matters

Webflow gave CleanStart a fast start: hosted, visual, and capable for small-scale editorial work. The new platform is a code-first Next.js 16 front end backed by a self-hosted custom Payload 3 CMS — eliminating structural performance ceilings, replacing hand-bolted SEO embeds with a programmatic engine, and owning the full stack from Postgres to CDN.

Faster, measurably

Mobile Lighthouse more than doubled (32 → 84) and desktop jumped from 61 → 98. Webflow's desktop TBT hits 3,150 ms — 63× the new site's 50 ms. The jQuery + interactions runtime is structural and non-removable on any Webflow plan.

Automated end-to-end

Ten scheduled jobs, a three-layer JSON-LD engine, automatic image derivatives, IndexNow pings, auto 301 redirects on slug changes, nightly broken-link scans, GDPR PII purges, a self-healing search index, and a fault-tolerant lead pipeline — none of which Webflow can do natively.

Owned & cheaper to scale

No per-seat editor fees, no CMS item caps, no API quotas. Media on Cloudflare R2 with zero egress fees. Full control of CSP, caching strategy and data — and a real migration path instead of vendor lock-in.

Honesty first. This is not a polemic against Webflow — it is a fast, well-built platform and right for many sites. Where the new build has genuine trade-offs (no drag-on-canvas WYSIWYG, ops burden of self-hosting, one mobile LCP weak spot), this document says so plainly. Every performance number is a real PageSpeed measurement; every capability claim ties to a source file; estimates are badged.

03 · Performance Architecture

Why the numbers differ — by design

The score delta is architectural, not accidental. Webflow ships a fixed client runtime you can never remove; Next.js lets us choose exactly how each route is delivered.

Old · Webflow
  • Fixed client runtime. Every page ships jQuery + underscore + webflow.js — render-blocking, non-removable on every plan including Enterprise.
  • JS-driven interactions. Animations run on the main thread, inflating Total Blocking Time — measured at 3,150 ms desktop / 1,890 ms mobile in the fresh Lighthouse run.
  • Publish = full rebuild. No incremental regeneration, no per-route cache control, no on-demand revalidation.
  • Opaque cache. CDN behaviour is the platform's; you cannot set route-level revalidation windows.
New · Next.js 16 App Router
  • Static-first + ISR. Pages pre-render and revalidate incrementally — proven live by x-nextjs-stale-time: 300 on staging's HTTP response.
  • Per-route rendering: SSG via generateStaticParams() for all article/detail pages; force-dynamic only where needed.
  • No forced runtime. Code-split React 19; JS ships only where interactivity exists.
  • On-demand purge via revalidateTag() — publishing in the CMS instantly invalidates exactly the affected pages.

08 · Extensibility & the Plugin Question

Webflow has no plugin model. The new stack is the extension layer.

A common misconception is that Webflow has a WordPress-style plugin marketplace. It doesn't. Extensibility runs through four constrained, client-side channels — and Webflow's "Logic" server-side automation was sunset on 27 June 2025 with no replacement.

Webflow extensibility — four channels
  • Custom-code embeds — capped at ~10,000 chars site-level, ~5,000 page-level. Applies on every plan including Enterprise.
  • Webflow Apps marketplace — vetted integrations (Finsweet, Jetboost, Memberstack…), not server plugins. Each is a separate subscription.
  • Zapier / Make — the official automation path now that Logic was sunset 27 Jun 2025. No native server-side automation remains.
  • Third-party JS libraries — Finsweet Attributes, Jetboost for search/filter, Memberstack for auth gating.
  • No backend, no scheduled jobs, no server runtime. All custom code is client-side.
New stack — full backend ownership
  • Arbitrary server logic — custom Payload collections, hooks, endpoints and access rules in TypeScript.
  • Ten scheduled background jobs running real server-side work (see Part B).
  • Integrations dashboard — Teams, HubSpot, GA4, GSC, Clarity, Cloudflare, Meilisearch, Cal.com — configured by editors without a code deploy.
  • No character limits, no client-only ceiling — the platform is the extension surface.
  • Trade-off: this power requires engineering ownership; Webflow's ceiling is also its simplicity.

New stack economics

  • No per-seat fees, no item caps, no API quotas — Payload is MIT-licensed, self-hosted.
  • Single Linode droplet (Postgres + Meilisearch + CMS via Docker), front end on Vercel.
  • R2 zero egress keeps media costs flat as traffic grows.
  • Typical infra cost for this class of self-host: ~$0–$50/mo vs $39+/seat stacking.
  • Trade-off: you carry ops, backups, patching and uptime — covered by GitHub Actions deploys, backup-cron heartbeats and Caddy-fronted health probes.

Vendor lock-in. Webflow code export ships static HTML/CSS/JS only — it excludes all CMS content and Collection-bound functionality (Collection Lists render empty; template pages don't generate). CMS data exits only through a rate-limited API. Leaving Webflow is a rebuild. The new stack is TypeScript + Postgres + S3-compatible storage — portable by construction, which is precisely how the Webflow → Payload migration was possible.

12 · Webflow → Payload Migration

A repeatable 4-stage ETL — with URL parity

Because Webflow code-export drops all CMS content, the migration was built as a proper ETL pipeline — idempotent, checkpointed, and URL-parity-aware.

H1 · EXPORT

Pull from Webflow API

12 collections, token-bucket throttled (50 req/min), checkpointed JSONL, fully resumable.

→
H2 · TRANSFORM

Map & convert

15 per-collection mappers; HTML body → Lexical JSON; SEO fields rebuilt; relationships scaffolded.

→
H3 · ASSETS

Upload to R2

Hash-dedup media; folder-tagged by content type; builds Webflow-URL → CDN-URL map for body rewriting.

→
H4 · IMPORT

Load via Local API

Dependency-ordered; idempotent lookup-by-slug; rewrites relationship IDs; row-level log.

SEO continuity built in. A URL-parity step emits redirects collection rows for every changed path, so previously-indexed Webflow URLs keep resolving. Acceptance checks validate row counts and body conversion post-import. Migrated content is immediately versioned, draftable and SEO-instrumented in the new CMS.
