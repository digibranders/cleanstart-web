Re-audit addendum — unstaged changes reviewed 2026-06-10

After the fleet audit completed, new unstaged work landed in the working tree and was manually re-reviewed against the findings. Affected findings below carry a teal re-audit chip inline.

What changed

  • robots.txt rebuilt as a route handler with Content Signals — src/app/robots.ts (metadata route) was replaced by src/app/robots.txt/route.ts + a pure builder in src/lib/seo/robots.ts (+7 passing tests), because MetadataRoute.Robots cannot emit non-standard directives. The new robots.txt declares Content Signals (search=yes, ai-input=yes, ai-train=yes on production, all-no on non-indexable hosts) — a net-new AI-agent-readiness capability not present at audit time. Host-aware gating, crawl rules, Bytespider block, Sitemap/Host lines are preserved exactly.
  • WEB-PRODUCTION.md substantially extended — New: DNS-AID publish runbook (Cloudflare API + dashboard) with HTTPS/SVCB record forms; a DNSSEC completion runbook; Content Signals documentation; a 'scanner items deliberately NOT implemented' decision table (6 intentional skips with rationale); markdown-for-agents known-limitations paragraph; pre-launch checklist items 19a–19c (agent discovery, DNS-AID, markdown negotiation verification).
  • api-catalog Content-Type header + markdown rewrite + Link discovery header — These were present (uncommitted) at audit time and were already reviewed by the fleet — unchanged since.

New gap surfaced

The doc update itself surfaces a real new infrastructure gap, verified by the author on 2026-06-10: the DNSSEC chain is broken at the parent — Cloudflare-side signing is enabled but the DS record was never added at the registrar (GoDaddy), so dig DS cleanstart.com is empty and resolvers return AD: false. DNS-AID specifies signed discovery zones, so the new _index._agents records won't validate until the DS step completes. The runbook to fix it is now in WEB-PRODUCTION.md §3.

Verification of the new code

Scoped checks on apps/web: lint ✓ (biome, 442 files) · typecheck ✓ (tsc --noEmit) · tests ✓ (23/23 across robots.test.ts, agent-markdown.test.ts, agent-discovery.test.ts). Production build not run — it requires a production-mode CMS instance for prerendering (known constraint).

Not affected

Findings NOT affected by these changes (still open): all P0 launch blockers (go-live flip contradiction, CSP nonce, Webflow 301s, IndexNow key, sitemap gaps, double brand suffix, draft-content API exposure, LCP at opacity:0), the entire Knowledge Hub cluster, and the host-awareness gap — the sitemap is still env-gated only (sitemap.ts:104 calls isIndexingAllowed() without a host).

Score impact: Content Signals is a genuine AI-agent-readiness improvement (one of the five scanner capabilities now implemented at robots level); the AI Agent Readiness dimension would score ~67–68 on a re-run. Dimension scores in this report are kept as-measured by the fleet for traceability.

Prioritized action roadmap

Context: the site is pre-launch (staging.cleanstart.com is the Vercel production target; indexing is intentionally gated). That makes most findings cheap to fix now and expensive to fix later — the P0 list is exactly the set that would cause a launch-day SEO incident.

P0 — Launch blockers (fix before go-live)

  1. Resolve the go-live flip contradiction — The canonical host is baked at build time, but the documented promotion procedure reuses the staging artifact with no rebuild — canonicals, OG URLs, and the sitemap would all carry the wrong host on day one. Decide apex vs www now and make the promotion path rebuild (or make the host runtime-resolved). Deployment & Serving #1/#4, Crawlability #5.
  2. Fix the CSP before the enforcement flip — The planned CSP enforcement will break the site as wired: the nonce is generated but never consumed, and inline style attributes (used heavily per the Figma-exact-values convention) are forbidden by the policy. Test in report-only against real pages first. Deployment & Serving #1 (verified, downgraded critical→high).
  3. Import the 26 legacy Webflow 301s — The redirect export exists but is imported nowhere and is absent from the go-live checklist; several targets also point at pages that no longer exist. Launch without it loses all legacy link equity. Deployment & Serving #3.
  4. Serve the IndexNow key file from apps/web — Every IndexNow ping from the CMS (12 wired collections) fails host verification because the key file isn't served on the web domain. One static file fixes it. CMS SEO #1, Deployment #2.
  5. Close the sitemap gaps — (a) /case-studies and /cleanstart-platform are indexable + nav-linked but missing from STATIC_ROUTES; (b) every /author/* URL silently drops out because the sitemap queries publishedAt, a field the authors collection doesn't have. Crawlability #1/#2 (both verified).
  6. Lock down draft content on the CMS REST API — Draft documents are publicly readable via the Payload REST API on every content collection — a content-leak and duplicate-content vector. CMS SEO #2 (verified).
  7. Fix the double brand suffix on CMS titles — Live pages render '… | CleanStart | CleanStart' because imported seo.title already contains the brand and the layout template appends it again. Strip the trailing brand in resolveCmsSeo + clean the affected docs. Metadata #1 (verified live on staging).
  8. Un-gate the LCP from JS hydration — HeroReveal/Reveal server-render hero H1s at opacity:0, so LCP waits for hydration on every page. Render above-the-fold content visible and animate progressively. Performance #1 (verified).
